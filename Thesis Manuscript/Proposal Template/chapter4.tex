\section{Design and Implementation}

This chapter presents the design and implementation of the proposed hybrid machine learning framework for identifying elevated fasting blood glucose risk using the 2018--2021 Philippine Expanded National Nutrition Survey (ENNS). It describes dataset preparation, the development of ten classification approaches, SHAP and LIME analysis, probability calibration, and Calibrated Explanations (CE). The chapter also outlines the experimental environment supporting the study's preliminary results.

\subsection{Methodological Pipeline Overview}

The pipeline comprised ENNS dataset integration, sentinel-value normalization, target construction, feature engineering, skip-logic recoding, imputation, outlier capping, standardization, and correlation filtering. The resulting 26 predictors were used in SMOTE balancing and stratified 70/15/15 partitioning, followed by model development, SHAP and LIME, probability calibration, and CE analysis. A methodological pipeline diagram is proposed to summarize these stages.

The ten approaches consisted of Na\"{i}ve Bayes, six tuned conventional classifiers, BO-TabNet, Voting, and Stacking. Explanations were obtained using SHAP and LIME. Platt Scaling, Isotonic Regression, and Temperature Scaling were compared for probability calibration, while the CE framework employed Venn-Abers calibration to produce uncertainty-aware explanations.

\subsection{Data Source}

\subsubsection{2018--2021 Expanded National Nutrition Survey}

The dataset used in this study is sourced from the 2018--2021 Expanded National Nutrition Survey (ENNS), conducted by the Food and Nutrition Research Institute (FNRI) under the Department of Science and Technology (DOST) of the Philippines. The ENNS is a nationally representative survey collecting data on health, nutrition, and socioeconomic characteristics of the Filipino population across all administrative regions.

Five ENNS components were examined. Four contributed to the modeling dataset, while the dietary component was excluded from the final predictors following preliminary analysis.

\subsubsection{Diabetes Risk Target Definition}

The target variable \texttt{diabetes} was derived from fasting blood sugar (FBS). Following the American Diabetes Association diagnostic criteria \cite{ada_diabetes_diagnosis}, individuals with FBS $\geq$ 100 mg/dL (prediabetes: 100--125 mg/dL; diabetes: $\geq$126 mg/dL) were assigned Class~1 (\textit{at risk}), and those with FBS $<$ 100 mg/dL were assigned Class~0 (\textit{not at risk}). Rows with missing FBS were removed before any imputation step to prevent imputation-induced label leakage.

\subsection{Preprocessing and Feature Engineering}

All preprocessing was implemented in Python using \texttt{Pandas}, \texttt{NumPy}, \texttt{scikit-learn} (version 1.5.2), and \texttt{imbalanced-learn} (version 0.13.0). The complete pipeline is executed by \texttt{main\_preprocessing.py}.

\subsubsection{Dataset Integration}

The anthropometric, biochemical, and clinical datasets were merged via a left join on \texttt{hhnum} and \texttt{member\_code}, using the clinical dataset as the anchor. The socioeconomic dataset was subsequently merged to extract \texttt{age} and \texttt{sex}. After merging, metadata columns (\texttt{regcode}, \texttt{provhuc}, \texttt{hhnum}, \texttt{member\_code}, and survey design codes) were excluded from the predictor set.

\subsubsection{ENNS Sentinel-Value Normalization}

The ENNS survey encodes non-applicable responses using survey-specific codes documented in the FNRI data dictionaries, such as \texttt{99} for \texttt{ever\_smk} and \texttt{9} for \texttt{con\_alcohol} and \texttt{drnk\_30days}. Before imputation, these codes were recoded to \texttt{NaN} to ensure they were treated as missing values.

\subsubsection{Target Construction}

Rows with missing FBS were removed before any feature imputation step, preventing imputation-induced label leakage. The binary target \texttt{diabetes} was constructed from the remaining records using the FBS threshold described in Section~4.2.3.

\subsubsection{Selective Feature Engineering}

Four candidate features were computed from raw anthropometric and biochemical measurements before imputation and scaling. Total cholesterol (\texttt{chol}) was retained alongside LDL because they are distinct laboratory measures, and weight and height were retained alongside the derived \texttt{bmi} because they are measurements that a user can supply.

\subsubsection{ENNS Skip-Logic Recoding}

Several ENNS questionnaire items are asked only when an earlier answer applies, and the survey leaves the dependent items blank otherwise. Treating these blanks as ordinary missing values would assign them the most frequent answer, which is incorrect. Respondents who had never consumed alcohol (\texttt{alcohol} = 0) were therefore assigned \texttt{con\_alcohol} = 0 and \texttt{drnk\_30days} = 0, and respondents with \texttt{con\_alcohol} = 0 were assigned \texttt{drnk\_30days} = 0. Current smokers were not asked the \texttt{ever\_smk} question, so blanks in \texttt{ever\_smk} for current smokers were assigned a separate code of 6. The variable \texttt{drnk\_30d\_num} (number of standard drinks) was excluded because about half of its values were blank and a further quarter carried an undocumented code of 999999 that was not a valid count.

\subsubsection{Missing-Value Imputation}

Missing values in continuous features were imputed using K-Nearest Neighbors (KNN) imputation with the number of neighbors $k$ optimized through cross-validation. Remaining blanks in categorical features that were not explained by skip logic were assigned an explicit missing category coded as $-1$ instead of the mode, so that no answer was invented. The resulting imputed values were used in subsequent data preparation.

\subsubsection{Outlier Handling}

Outliers in continuous features were capped using the interquartile range (IQR) method with a 1.5$\times$IQR boundary. Values below $Q_1 - 1.5 \times \mathrm{IQR}$ were set to the lower bound, and values above $Q_3 + 1.5 \times \mathrm{IQR}$ were set to the upper bound.

\subsubsection{Standardization}

Continuous predictors were standardized using \texttt{StandardScaler}. Categorical predictors were not standardized.

\subsubsection{Correlation-Based Feature Elimination}

Pearson correlation was computed across all features on the training partition. A protected list of measurements and questionnaire answers that a user can supply (\texttt{weight}, \texttt{height}, \texttt{bmi}, \texttt{waist}, \texttt{hip}, \texttt{chol}, \texttt{ldl}, \texttt{tri}, \texttt{hdl}, \texttt{currentsmoking}, \texttt{ever\_smk}, and \texttt{smoke\_status}) was exempted from removal. For each pair with $|r| > 0.80$, the unprotected feature was removed when only one feature of the pair was protected, the later feature was removed when neither was protected, and both features were kept when both were protected. Because the redundant derived features were dropped beforehand, the filter removed no further features. The final 26-predictor set is described in Table~\ref{tab:final_features}.

\subsubsection{Class-Imbalance Handling}

The dataset exhibited class imbalance, with not-at-risk cases substantially outnumbering at-risk cases. SMOTE \cite{elreedy_smote_2023} was applied to the full preprocessed dataset with \texttt{sampling\_strategy = 1.0} (full 1:1 balance) and \texttt{k\_neighbors = 5}. The resulting balanced dataset was subsequently partitioned into training, validation, and test sets.

\subsubsection{Train-Validation-Test Partition}

The balanced dataset was partitioned using a stratified 70/15/15 split with \texttt{random\_state = 42}:

\begin{itemize}
    \item \textbf{Training set (70\%):} used for model fitting and RandomizedSearchCV cross-validation
    \item \textbf{Validation set (15\%):} used for Optuna BO-TabNet optimization and post-hoc calibration fitting
    \item \textbf{Test set (15\%):} used to calculate and compare reported model performance
\end{itemize}

\subsection{Model Development and Optimization}

All classifiers were implemented in Python 3.12.2 using \texttt{scikit-learn} (version 1.5.2), \texttt{pytorch-tabnet} (version 4.1.0), \texttt{xgboost} (version 3.2.0), \texttt{lightgbm} (version 4.6.0), \texttt{catboost} (version 1.2.10), and \texttt{optuna} (version 4.8.0). \subsubsection{RandomizedSearchCV Optimization}

For the six tunable traditional classifiers, \texttt{RandomizedSearchCV} was used with F2-score as the scoring function and 5-fold cross-validation on the training set. Search spaces included learning rate, tree depth, and estimator count for boosting models, neighbor count and distance metrics for kNN, and estimator count and learning rate for AdaBoost.

\subsubsection{Bayesian Optimization of BO-TabNet}

BO-TabNet was optimized using Optuna with the TPE sampler over 30 trials, evaluating F2-score on the validation set. The search covered decision and attention dimensions, decision steps, the relaxation parameter, sparsity regularization, learning rate, and batch size.

\subsubsection{Voting and Stacking Ensemble Construction}

Both ensemble classifiers used the same three optimized base learners: Random Forest, XGBoost, and LightGBM.

\textbf{Voting Ensemble:} Implemented with \texttt{VotingClassifier} (\texttt{voting=`soft'}). The predicted probability was the unweighted mean of the base learners' probabilities.

\textbf{Stacking Ensemble:} Implemented with \texttt{StackingClassifier}. Out-of-fold predictions from the three base learners (via 5-fold CV) served as meta-features for a Logistic Regression meta-learner, to combine the base-model outputs.

\subsubsection{Model-Selection Protocol}

The ten models were compared primarily using F2-score, supported by Recall, ROC-AUC, and AUPRC. Log-Loss and Brier Score were also reported to examine probability quality. This evaluation distinguished recall-oriented screening performance from probability reliability.

\subsection{Explainable Artificial Intelligence Techniques}

SHAP and LIME were used to interpret the predictions of the trained classifiers. Both techniques are discussed theoretically in Chapter~3, while this section specifies their use in the study.

\subsubsection{SHAP}

The \texttt{shap} library was used to generate local attributions and aggregated feature rankings. Tree-based models were analyzed using \texttt{TreeExplainer}, while model-agnostic approximation was used where appropriate. Outputs included summary plots, global feature importance, and individual explanation plots.

\subsubsection{LIME}

The \texttt{lime} library was used to explain selected individual predictions. \texttt{LimeTabularExplainer} generated local perturbations and fitted weighted surrogate models to identify the features influencing each prediction. These outputs complemented SHAP's global and local attribution analysis.

\subsection{Probability Calibration}

Three post-hoc calibration methods were evaluated using validation-set predictions: Platt Scaling, Isotonic Regression, and Temperature Scaling. Platt Scaling fitted a sigmoid mapping, Isotonic Regression fitted a monotonic mapping, and Temperature Scaling adjusted prediction logits through a learned temperature parameter. Their mathematical formulations are presented in Chapter~3. Calibration was applied to all ten classification approaches, and the method retained for each model was selected by five-fold cross-validated Log-Loss on the validation set.

Calibration configurations were compared using Log-Loss as the main criterion, with Brier Score and Expected Calibration Error (ECE) as supplementary measures. Reliability diagrams visualized the agreement between predicted probabilities and observed positive-class frequencies. The calibration comparison was reported separately from the Venn-Abers procedure used within CE.

\subsection{Calibrated Explanations Implementation}

The \texttt{calibrated-explanations} library was applied to nine classifiers, excluding BO-TabNet because of estimator-interface compatibility constraints \cite{lofstrom_ce_2024}. Validation data served as the Venn-Abers calibration set, while selected test observations were used for explanations. Four analyses were conducted.

\subsubsection{Factual CE}

Six test observations per model, comprising three predicted at-risk and three predicted not-at-risk cases, were explained using calibrated probabilities, probability intervals, and feature-weight intervals. Outputs were saved under \texttt{MAIN\_CE\_OUTPUT/factual/}.

\subsubsection{Counterfactual CE and Ensured CCE}

The same six observations per model were used for Counterfactual CE (CCE) and Ensured CCE. These analyses examined alternative feature conditions and their associated calibrated predictions and uncertainty estimates. Outputs were saved under \texttt{MAIN\_CE\_OUTPUT/counterfactual/}.

\subsubsection{Global CE}

Factual explanations from 150 test observations per compatible model were aggregated to summarize feature importance and its variability. Results were stored under \texttt{MAIN\_CE\_OUTPUT/global/}.

\subsubsection{Mondrian CE}

Mondrian CE was conducted for 50 test observations per sex group per model, using group-conditional Venn-Abers calibration \cite{lofstrom_conditional_ce_2024}. The resulting comparisons characterized differences in prediction intervals and explanatory patterns across groups. Results were stored under \texttt{MAIN\_CE\_OUTPUT/mondrian/}.

\subsection{Technical Architecture}

This section presents the proposed software architecture and technical requirements of the web-based diabetes risk assessment system. It describes the integration of trained machine learning models, probability calibration, and explainability methods into the proposed application.

\subsubsection{Proposed System Architecture}

The proposed application will follow a three-layer architecture consisting of the presentation, application, and model layers. The presentation layer will provide the interface for entering health information and viewing risk assessments. The application layer will handle input validation, model inference, probability calibration, and explanation generation. The model layer will contain the saved preprocessing components, trained classifiers, and calibration artifacts.

The system will integrate SHAP and LIME for model explanations and Calibrated Explanations (CE) for uncertainty-aware predictions and counterfactual analysis. The specific web development framework will be determined during application implementation.

The machine learning pipeline was developed using Python and supporting libraries for preprocessing, model training, calibration, and explainability. These included scikit-learn, XGBoost, LightGBM, CatBoost, PyTorch, SHAP, LIME, and Calibrated Explanations. \subsubsection{Web Application Requirements}

The proposed application will be accessible through a modern web browser on a computer or mobile device. Users will be able to submit health information and view the corresponding risk assessment without installing the machine learning software locally. Internet connectivity will be required if the application is hosted remotely.

The application will serve as an exploratory decision-support tool and will not replace professional medical diagnosis.
